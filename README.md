\## 🌿 コミットメッセージ、ブランチ名の命名規則



チーム全員がスムーズに開発を進め、アセットの競合（コンフリクト）を未然に防ぐための共通ルールです。



\### 1. コミットメッセージ規則

履歴（History）をパッと見て変更内容が1秒で理解できるよう、メッセージの先頭に指定の \*\*Gitmoji\*\* と \*\*prefix\*\* をつけてください。



> 📌 \\\*\\\*フォーマット:\\\*\\\* `\\\[Gitmoji] \\\[prefix]: \\\[変更内容の要約] (#Issue番号)`

> 💡 \\\*\\\*例:\\\*\\\* `✨ feature: プレイヤーのダッシュ機能を実装 (#12)`



| Gitmoji | prefix | 対象となる作業内容 |

| :---: | :--- | :--- |

| ✨ | \*\*`feature`\*\* | 機能（追加） |

| 📦 | \*\*`asset`\*\* | データ・素材の追加・調整（アセットのインポートなど） |

| 🐛 | \*\*`fix`\*\* | バグ修正・不具合対応 |

| 🎨 | \*\*`adjust`\*\* | パラメータ・手触りの調整（数値変更、エフェクト微調整、ブラッシュアップ） |

| ♻️ | \*\*`refactor`\*\*| 動作を変えない改善（コードの清書やフォルダの整理など） |



\#### 💡 コミットのコツ

\* 迷ったら `feature` や `asset` などの大まかな分類で進めてOKです。ルールの厳格さよりも開発のスピードを優先しましょう！



\### 2. ブランチ命名規則

ブランチは\*\*半角英数字のみ\*\*で作成し、以下の prefix（接頭辞）を使用してください。

コンフリクトを防ぐため、先頭に「\*\*担当者名/\*\*」をつけ、末尾に「\*\*Issue番号\*\*」と内容を記述します。



> 📌 \*\*フォーマット:\*\* `\[担当者名]/\[prefix]-\[Issue番号]-\[わかりやすい内容]`

> 💡 \*\*例:\*\* `tanaka/feature-12-player-dash`



| prefix | 対象となる作業内容 |

| :--- | :--- |

| \*\*`feature`\*\* | 新機能の追加、ゲーム要素（システムやステージ）の新規実装 |

| \*\*`asset`\*\* | 3Dモデル、テクスチャ、音、エフェクトなどのデータ・素材の追加・調整 |

| \*\*`fix`\*\* | バグ修正、不具合の対応、クラッシュ対策 |

| \*\*`adjust`\*\* | 攻撃力などのパラメータ、ゲームの手触り、見た目の微調整 |

| \*\*`refactor`\*\*| 動作（ゲームの見た目や挙動）を変えない、コードやフォルダの整理・改善 |
